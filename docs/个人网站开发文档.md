# 个人网站开发文档

Nov 4, 2026 · @Lxjn Long

## 概述与技术选型

本项目分为两个前端应用和一个后端服务：用户端用 Nuxt + Naive UI（服务端渲染，兼顾 SEO），管理端用 Vite + Element Plus（单页应用）。两端分别按「个人网站设计稿」和「个人网站管理端设计稿」实现。

| 层 | 用户端 | 管理端 | 说明 |
| --- | --- | --- | --- |
| 框架 | Nuxt（Vue 3，SSR） | Vue 3 | 都用 `<script setup>` + TypeScript |
| 构建 | Nuxt 内置（Vite） | Vite | 包管理统一用 npm，镜像源 npmmirror |
| 组件库 | Naive UI | Element Plus | 主色都是 #409EFF |
| 样式 | SCSS | SCSS | 颜色取自组件库主题变量，不在 SCSS 里写死 |
| 路由 | 按 pages/ 目录自动生成 | Vue Router 4 | 用户端无需手写路由表 |
| 状态 | useState / Pinia（@pinia/nuxt） | Pinia | 用户端不得在模块顶层定义共享状态 |
| 请求 | useFetch / $fetch | Axios | 用户端首屏数据用 useFetch，事件触发用 $fetch |
| 工具 | @vueuse/core | @vueuse/core |  |
| Markdown | markdown-it + highlight.js | md-editor-v3 或 Milkdown | 用户端在服务端渲染正文并生成目录 |
| 图表 | — | ECharts | 仪表盘访问趋势 |
| 国际化 | @nuxtjs/i18n | vue-i18n | 一期中文 + English，其他语言后加 |
| 样例数据 | Nuxt server/api | — | 后端确定前用于渲染，见「个人网站接口文档」 |

后端语言尚未确定，接口按 REST + JSON 约定，统一以 `/api` 开头，详见「个人网站接口文档」；Spring Boot、NestJS 等都可以实现。

## 项目结构

两个前端各自独立成项目，用 npm 管理依赖：仓库 blog-ui 只放用户端（Nuxt），管理端以后单独建项目。用户端目录如下：

```
blog-ui/
  app.vue                 # 根组件：n-config-provider（主题、语言）
  nuxt.config.ts          # 模块、SCSS、i18n、/api 代理
  layouts/default.vue     # 背景层 + SiteHeader + 内容 + SiteFooter
  pages/                  # index / projects / blog/index / blog/[slug] / about
  components/             # SiteHeader、SiteFooter、FullPage、BgLayer、GlassCard 等
  composables/            # useSite、useTheme 等
  types/api.ts            # 接口类型
  i18n/locales/           # zh-CN.json、en.json
  assets/styles/          # 全局 SCSS、自定义 CSS 变量
  server/api/             # 样例接口（/api/**）
  server/mock/            # 样例数据
  server/routes/rss.xml.ts
  public/
```

- 两端分开打包：用户端要小、要快，管理端的编辑器、ECharts 等重依赖不会出现在用户端的包里。
- 用户端需要一个 Node 进程运行（Docker 或 pm2）；管理端是静态文件，放在 Nginx 的 /admin 下。
- Nuxt 编码规范：浏览器 API（window、localStorage 等）只在 onMounted 或 `<ClientOnly>` 中使用；主题和语言偏好存 Cookie，避免首屏闪动。

## 设计规范

两端用同一套色值：用户端写进 Naive UI 的 `themeOverrides.common`，自定义样式用 `useThemeVars()` 取色；管理端沿用 Element Plus 的 CSS 变量。背景层和毛玻璃的几个自定义变量两端各自定义一份，取值相同。

### 字体、间距、圆角

- 字体栈：`"Helvetica Neue", Helvetica, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", Arial, sans-serif`。
- 字号：首页名字 40px，页面标题 32px，区块标题 24–28px，正文 16px（行高 1.8），界面 14px，辅助 12px。
- 间距阶梯：4 / 8 / 12 / 16 / 20 / 24 / 32 / 64px。
- 圆角：按钮、输入框 4px，卡片 8px，登录卡片 12px，头像 50%。
- 布局：用户端内容最大宽 1200px，左右 24px（手机 16px）；正文阅读宽度 ≤ 720px；管理端侧边栏 220px、顶栏 56px。
- 断点：≤ 768px 卡片单列、导航换行、首页整屏滚动退化为普通滚动。

### 背景层与毛玻璃

全站只有一个背景层，三种样式在站点设置 › 外观中切换：纯色、光晕（两个浅色径向渐变）、背景图。使用背景图时必须叠一层 60%–80% 的浅色蒙层，否则文字不可读。内容卡片统一用 `--glass-bg` + `backdrop-filter: blur(12px)`，不用实心白底。登录页背景单独配置，默认跟随站点，图片模式下用暗色蒙层。

### 暗黑模式

设计稿只画了亮色。用户端一期直接用 Naive UI 自带的 `darkTheme`：在 `n-config-provider` 上切换 `:theme`，并给暗色主题配一份同样主色的 `darkThemeOverrides`；用户偏好存 Cookie，服务端渲染时就按正确主题输出，避免闪动。自定义变量（`--site-bg`、`--glass-bg`、`--glass-border`）先在 `html.dark` 下简单补一组深色值，后续再细调。管理端引入 `element-plus/theme-chalk/dark/css-vars.css`，用 `useDark()` 切换。

## 用户端页面与路由

用户端共 5 个页面，全部套用同一个布局（背景层 + SiteHeader + 内容 + SiteFooter），只有首页使用整屏滚动。

| 路由 | 页面 | 主要内容 | 接口 |
| --- | --- | --- | --- |
| / | 首页 | 3 屏：介绍（头像、名字、身份、两行简介、联系图标）→ 精选项目（最多 3 个）→ 技术栈 + 页足 | GET /api/profile、GET /api/projects?featured=1、GET /api/skills?home=1 |
| /projects | 项目列表 | 分类筛选（全部 / Web / 工具 / 硬件）、三列卡片、状态标签 | GET /api/projects |
| /blog | 博客列表 | 搜索、文章列表、分页；侧栏：作者卡、分类、标签云 | GET /api/posts、GET /api/categories、GET /api/tags |
| /blog/:slug | 文章详情 | 面包屑、标题与元信息、Markdown 正文、目录（n-anchor）、标签、上下篇 | GET /api/posts/:slug |
| /about | 关于 | 个人介绍卡、技术栈（主力 / 了解）、工作经历时间线 | GET /api/profile、GET /api/skills、GET /api/experiences |

全站布局另请求 GET /api/site（站点配置）和 GET /api/friend-links（页足友链）。英文页面地址加 /en 前缀（如 /en/blog），由 @nuxtjs/i18n 生成。

### 首页整屏滚动

1. 根容器 `height: 100vh; overflow: hidden`，内部轨道靠改变 `top` 切屏（`transition: top .8s`）。不要用 `transform`：它会让页足里的友链弹窗（`position: fixed`）相对轨道定位，弹窗会跑出屏幕。
2. 滚轮事件节流 900ms，每次只切一屏；右侧圆点和上下箭头也能切屏，键盘 ↑ ↓ / PageUp PageDown 建议一并支持。
3. 头部栏在第 1 屏透明、与页面融为一体，切到第 2 屏起加 `is-solid`（半透明白 + 模糊 + 底部线）。
4. ≤ 768px 或站点设置中关闭「首页整屏滚动」时，退化为普通纵向滚动，分屏导航隐藏。

### 友链申请弹窗

页足「+ 申请友链」打开，顶部展示本站信息并可一键复制。字段：网站名称、网站地址、联系邮箱（必填），头像地址、简介（≤ 50 字）、本站链接所在页面（选填）。提交前做人机验证，成功后切到「申请已提交」状态，调用 `POST /api/friend-links/apply`。「开放前台申请」关闭时不显示入口。

### 页足

全站统一：站点名 + 签名 + 联系图标、友情链接（已通过的）+ 申请入口、站点导航（含「管理后台」入口，指向 `/admin`）、版权声明和备案号。

## 接口设计

接口前缀统一为 `/api`，不带版本号：公开接口 `/api/*`（用户端、无需登录），登录 `/api/auth/*`，管理接口 `/api/admin/*`（需登录 Token 或有权限的 API Key）。返回统一为 `{ code, message, data }`，列表带 `{ list, total, page, size }`。完整的接口清单、参数、返回示例、错误码和 TypeScript 类型见 个人网站接口文档。

## 登录与安全

管理端只有一个管理员账号，支持 5 种登录方式，开关在「站点设置 › 登录设置」中，账号密码登录不可关闭。

| 方式 | 前提 | 流程要点 |
| --- | --- | --- |
| 账号密码 | — | 连续输错 3 次后要求人机验证；5 次锁定 15 分钟（可配置） |
| 手机验证码 | 已绑定手机 + 短信服务 | 点「获取验证码」先过人机验证，再发 6 位码，5 分钟有效，60 秒后可重发 |
| 邮箱验证码 | 已绑定邮箱 + SMTP | 同上；「忘记密码」也走这条路 |
| 扫码登录 | 选定扫码 App | 生成一次性二维码，前端轮询状态；2 分钟失效，显示刷新蒙层 |
| 第三方账号 | 已配置应用 + 已绑定 | OAuth 2.0 授权码流程；未绑定的账号不能登录，只提示去账号安全里绑定 |

- 会话：登录成功后签发 Access Token（短期）+ Refresh Token（HttpOnly Cookie），「7 天内免登录」决定 Refresh Token 的有效期。
- 人机验证：前端只负责拿到服务商的票据，校验必须在后端完成；设计稿中的拼图只是占位，不要自己实现。
- 登录页第三方图标使用各平台官方素材，并遵守其品牌规范；只显示已启用的服务商。
- 账号绑定：更换或解绑手机、邮箱、第三方账号前验证当前密码；密码始终保留，所以不会把自己锁在外面。
- 每次登录（含失败）写入 `login_log`，账号安全页展示最近 5 条，含登录方式和结果；新设备或新地点登录时发邮件提醒。

## 自定义启动横幅

可在 [patorjk.com](https://patorjk.com) 的 ASCII 字体生成器中制作横幅，再将生成的文本复制到 `banner.txt`。

在用户端进程的运行目录下放置 UTF-8 编码的 `banner.txt`，可替换横幅正文并保留文件中的缩进。也可通过环境变量 `NUXT_BANNER_PATH` 指定其他文件，相对路径以运行目录为基准。文件缺失、内容为空或读取失败时，使用内置的 `blog` 横幅。横幅下方的应用版本由程序自动输出。

## 数据库与文件存储

数据库只有一个连接，文件存储可以配置多个存储库，其中一个为默认，都在「系统配置」页管理。

### 数据库

- 当前用户端支持 MySQL（默认 3306）和 SQLite（单文件）。连接配置可通过环境变量指定文件路径。
- 管理端负责初始化和升级数据库。切换数据库时先验证新库能连接，并完成必要的初始化或升级，成功后才切换。
- 模块版本表使用整数编号标识数据库、用户端、管理端 UI、管理端后台。数据库版本在迁移成功后登记，应用版本从各自发布产物的版本文件同步。用户端在数据库就绪前显示维护页，并在后台重试。
- 密码加密保存，表单留空表示不修改。
- 备份：自动备份（每天 / 每周 / 每月）、保留份数、备份到哪个存储库；支持立即备份、下载、恢复。恢复前先自动做一次备份。

### 文件存储

| 类型 | 配置项 | 说明 |
| --- | --- | --- |
| 本地存储 | 存储目录、访问路径 | 系统自带，作为兜底 |
| S3 兼容 | 服务商、Endpoint、Region、Bucket、AccessKey、Secret、路径前缀、访问域名 / CDN | 一套代码覆盖阿里云 OSS、腾讯云 COS、七牛、MinIO、AWS S3 |

- 新上传的文件进入默认存储库；切换默认库不移动已有文件，旧文件仍按 `file.repo_id` + `file.url` 访问。
- 默认库不能删除；非默认库只有没有文件引用时才能删除。
- 上传规则：文件命名（年/月/随机串、日期/原名、哈希去重）、单个文件上限、自动转 WebP、400px 宽缩略图、水印、去除 EXIF（默认开启，避免暴露拍摄位置）。
- 文件详情的「被引用」：保存文章和项目时解析其中的文件地址，记录引用关系，删除文件前提示。

## AI 助手与开发者 API

AI 功能和开发者 API 都是可选项，关闭后网站照常工作，可以放在二期实现。

### AI 助手

- **模型服务**：可配置多个，一个为默认；接口类型支持 OpenAI 兼容、Anthropic、本地 Ollama。通义千问、DeepSeek、Kimi 等国内服务大多可按 OpenAI 兼容接入。
- **后台写作助手**：文章编辑页右侧面板 + 选中文字浮动工具栏。动作：标题建议、生成摘要、推荐标签、润色选中、续写、生成大纲、自由对话；每个动作在设置中有独立开关。
- **结果落地**：AI 不直接改正文。润色结果以增删对比展示，由作者点「替换原文 / 插入到下方 / 放弃」；摘要点「填入文章设置」。
- **访客问答**：默认关闭。开启后网站右下角显示入口；回答范围默认「仅基于本站内容」（文章、项目、资料做检索增强），找不到答案时直接说明；每位访客每天 20 次。
- **用量与预算**：按月统计 tokens 与估算费用；超出预算后仅停用访客问答，或停用全部 AI 功能。
- 所有 AI 调用都经后端转发，模型的 API Key 不下发到浏览器。

### 开发者 API Key

- 用途：脚本、CI、第三方工具调用本站接口，如自动发布文章、同步项目。
- 格式 `sk-` + 随机串，创建后只显示一次，数据库仅存哈希和后 4 位；请求头 `Authorization: Bearer <API Key>`。
- 权限按范围勾选：文章读 / 写、项目读 / 写、文件上传、友链读取；任何 Key 都不能修改账号、登录和系统配置。
- 有效期 30 天 / 90 天（默认）/ 1 年 / 永不过期；可设 IP 白名单；可随时停用。
- 限制：每个 Key 每分钟 60 次；跨域来源白名单；调用日志保留 30 天。
